Set up and run offline

Use a macOS or Linux terminal with uv and Python 3.11 or newer. Open the repository root containing pyproject.toml and uv.lock. The initial install may download dependencies.

uv sync --locked
uv run --offline --no-sync fifth-pick health
sh final-project/scripts/course-demo.sh

The course script uses bundled synthetic data and shows a positive proposal and a zero-pick result. After setup, the script and Demo Mode run offline without provider credentials or OpenCode.

For the classroom walkthrough, stay in Demo Mode. The displayed projections, approvals and results are synthetic. The application records decisions and outcomes locally.

Walk through the demo menu

uv run --offline --no-sync fifth-pick menu

Use ↑ and ↓ to move, Enter to select, Esc to go back or cancel, and Q to exit from a menu or result screen. Confirmation screens start on Cancel. Choose Continue to proceed.

The main menu summarizes verified snapshot, decision, and results progress. The pointer marks the selected option. The separate Next Action section offers guidance based on the saved run. A proposal with selections still requires Joseph’s decision.

  1. Choose Analyze NBA Slate twice to record synthetic Snapshots 1 and 2.
  2. Open View Candidates and Rankings to compare candidates in one table. Before T-20, the table shows a numbered provisional watchlist. After T-20, it shows saved ranks and recorded review conclusions when available. Pending confidence means no assessment is available.
  3. Choose Run T-20 Review. This records Snapshot 3 and rechecks candidates at the fixture’s simulated twenty-minute checkpoint.
  4. Choose View Final Recommendations and confirm creation of the proposal. The positive example shows Luka Doncic, PrizePicks, Assists Higher 9.5, HIGH confidence and STILL STRONG at T-20.
  5. Choose Record Results before approval to see the settlement guard.
  6. Open Approve / Reject / Modify to see the exact proposal and the decision form. Joseph enters APPROVE, REJECT, or MODIFY in any capitalization. The menu also accepts A, R, and M. Enter a reason for rejection or a comma-separated list of the proposal’s selection numbers to keep. The provisional watchlist has separate candidate numbers. Standalone technical commands use full candidate keys. Esc closes the form before submission.
  7. Open View Audit and Receipts for decisions, evidence, and results. Use Full Audit JSON to see complete identifiers.

After recording Snapshot 1, find the run ID in View Audit and Receipts. Reopen the same run using uv run --offline --no-sync fifth-pick menu --run-id RUN_ID with that ID substituted.

Run the same workflow from the shell

From the repository root, run the lines in order in one shell. Choose a fresh run ID for each new scenario and keep it the same throughout the run.

fp() { uv run --offline --no-sync fifth-pick "$@"; }
run_id="course-$(date +%Y%m%d-%H%M%S)-$$"
demo=final-project/src/fifth_pick/demo

fp analyze --run-id "$run_id" --snapshot 1 --fixture "$demo/1"
fp analyze --run-id "$run_id" --snapshot 2 --fixture "$demo/2"
fp candidates --run-id "$run_id"
fp t20 --run-id "$run_id" --fixture "$demo/3"
fp final --run-id "$run_id"
fp audit --run-id "$run_id"
fp evaluate --run-id "$run_id"

Use fp decide --run-id "$run_id" to open the explicit decision form. For an approved fixture pick, replace CANDIDATE_KEY in fp result record --run-id "$run_id" --selection 'CANDIDATE_KEY' with its exact key. Use the values above and enter fixture:results/CANDIDATE_KEY as the shell command’s settlement reference. Rerun audit and evaluate to see the new records.

Supported inputs and outputs

ItemWhat to enter or inspect
Fixture inputThree stage directories each supply events.json, odds-<eventId>.json and stage.json. The stage descriptor supplies fixture mode, a timezone-aware observation timestamp, exact aliases and supporting evidence keyed to candidate IDs. The runbook describes the schema.
Board linesPrizePicks and Underdog stay separate. Supported categories are points, assists, rebounds, points + rebounds + assists (PRA), and rebounds + assists. Each line requires a resolved canonical player and the exact authorized category and Higher or Lower direction.
Proposalfinal reports the exact line, confidence, projection movement, T-20 status and material risks for each retained candidate. An empty proposal displays NO ENTRY RECOMMENDED TODAY.
SettlementEnter HIT, MISS, PUSH, VOID, DNP or RESULT UNAVAILABLE. Choose RESULT UNAVAILABLE when trustworthy settlement evidence is missing.
Audit and evaluationaudit emits JSON with the saved evidence and receipt trail. evaluate reports process checks and recorded outcomes separately. Run artifacts are under var/fifth-pick/runs/RUN_ID/, including receipts.jsonl.

Standalone and agent-assisted operation

Standalone CLI

The menu and the shell workflow both exercise the Python application directly. A Demo Mode decision can be recorded without dispatching an independent Reviewer. The CLI runs the fixture checks and persists the resulting evidence.

Native OpenCode review

In a configured OpenCode 1.18.20 environment, use opencode debug skill to list discovered skills and opencode debug agent fifth-pick-reviewer to inspect the resolved native tools before starting review. The native route requires a configured model. Superpowers skills appear in discovery when installed on the host. The offline course script uses the checked-in fixtures and Python CLI.

In the configured OpenCode workflow, Joseph authorizes the task. The Controller coordinates a Planner, Builder and independent read-only Reviewer, then brings the result back to Joseph. The Controller exports the exact JSON envelope with fifth-pick review-material --run-id RUN_ID, passes it to /fifth-pick-review in OpenCode and checks the persisted disposition with fifth-pick review-status --run-id RUN_ID.

In a fresh Controller session, start with fifth-pick review-handoff --run-id RUN_ID. Compare the proposal and artifact digests with the handoff. The compact record gives a next step and always reports dispatch_authorized: false. Inspect review-status for verified findings. If the checkpoint says CONFIRM_INITIAL_REVIEW_NOT_ATTEMPTED, confirm that no attempt occurred. Reconcile interrupted or uncertain review with Joseph.

A first FAIL can lead to one Controller-dispatched Builder correction after /fifth-pick-review-dispatch confirms a newly persisted REVISION_ATTEMPT. Malformed or mismatched review evidence blocks the workflow. CONCERNS and a second FAIL stop automated correction and go to Joseph. M10 was accepted with qualification under OpenCode 1.18.20. Edit and shell-write tools were withheld from the native Reviewer. Use Route A only. Correlated request-to-denial evidence remains blocked for both write routes. LIVE second-FAIL or CONCERNS escalation remains unverified. See the harness and gate record.

LIVE board operation

Live Mode is separate from the classroom fixture. The approved fantasy board route is The Odds API us_dfs. LIVE collection requires verified scope and Joseph’s explicit paid-request budget. Real observation windows, complete required evidence and a pre-tipoff owner decision govern a LIVE run. Consult the operations runbook and the LIVE operational amendment for prerequisites and review rules.

Troubleshooting

uv or fifth-pick cannot be found
Check that uv --version works, then run uv sync --locked from the repository root and repeat the offline health check.
The interactive menu will not open
Run the menu in a macOS or Linux terminal with interactive input and output, or use the shell commands or course script.
The watchlist is provisional
Complete both analysis stages, then use t20 with --fixture pointing to stage 3. Run final after review.
A replay stops or a receipt is inconsistent
Verify the run ID and stage path. Preserve the existing artifacts. Start a new scenario with a fresh ID.
The proposal has zero picks
Use audit to see candidate exclusions and evidence gaps. The empty result is a valid outcome.
Settlement is blocked
Check for an explicit saved approval and use the exact candidate key from its official final set. Inspect audit to see the current state.
