Technical design

A Python CLI for NBA fantasy selection and discipline. It assembles auditable proposals from authorized evidence and leaves the decision with Joseph.

Architecture

Discover slate → collect observations → evaluate candidates → review at T−20 → finalize proposal → independent review → Joseph’s decision → settlement and evaluation

fifth-pick exposes a menu and explicit subcommands. Demo defaults to packaged synthetic inputs. LIVE operations use application-owned storage and read back the run’s receipts and durable artifacts before advancing. The CLI has no platform login, entry submission, wager execution, or money movement. CLI entry points · Product requirements

Evolution 6’s context model preserves canon (stable instructions and decisions), runtime ledger (what execution observed), and derived views (summaries and status). Ledger evidence resolves what happened when a derived view is stale. In Fifth Pick, policy authority comes from the frozen design, approved amendments, and validated configuration. Receipts establish what a run actually did, and CLI views are reconstructed from underlying evidence. Evolution 6 context model · Evolution 6 handoff · Design analysis ledger

Methodology and deterministic controls

  1. Observe three times. Snapshot 1 is the initial accepted observation. Snapshot 2 targets the midpoint between Snapshot 1 and T−20, capped at T−80, with a 60-minute separation when achievable. Snapshot 3 is the accepted observation in the inclusive T−25 to T−20 interval. A missed window stays missed. Observation rules
  2. Evaluate evidence. Check last eight games, same-season head-to-head by exact opponent, availability, role and minutes, matchup, and game environment when required. Record conflicts and gaps with provenance. Senior HIGHER has ranking priority, Senior LOWER has stricter evidence requirements, and foul trouble and movement are contextual signals. Confidence is HIGH, MEDIUM, or LOW. These are qualitative judgments with deterministic validation and ordering. Frozen methodology · Evidence validation
  3. Freeze the pool and recheck. The receipt-bound full slate sets a ceiling of four picks for one to four games and five for five or more. Each canonical player can occupy one slot. LIVE review completes from T−20 through T−15 inclusive, with moving evidence retrieved at or after T−20 and by completion. Wait for outstanding reviews still inside their event windows, omit expired candidates, and keep vacancies open. Joseph alone can promote LOW. If the slate cannot support an entry, the CLI can emit NO ENTRY RECOMMENDED TODAY. LIVE timing and release · Pool and ceilings
  4. Settle with provenance. Approval is explicit, applies to the exact reviewed LIVE selection, and must precede tipoff and settlement. DNP and VOID have separate result statuses. Untrustworthy or absent evidence yields RESULT UNAVAILABLE. Process compliance and settlement outcomes are evaluated separately. Settlement · Evaluation

Governance and OpenCode permissions

Joseph → Controller → Planner → Builder → independent Reviewer → Controller → Joseph

The Controller owns progression and the one permitted correction. Planner, Builder, and Reviewer have separate OpenCode role definitions. The local skills for candidate evaluation, evidence validation, final-slate review, and T−20 prescribe procedure. Python and native permissions enforce the controls. Governance and rules · Project skill definitions

OpenCode role boundaries
RoleResponsibility and permissions
PlannerProduces bounded plans. Edit, Bash, task dispatch, and the legacy graduate-triage MCP write tool are denied. Planner definition
BuilderImplements approved changes. Edit is allowed. Bash defaults to deny with a short inspection, environment, health, and gate allowlist. Task dispatch and the MCP write tool are denied. Builder definition
ReviewerIndependently returns a strict JSON verdict with status, summary, and findings. Edit, Bash, task dispatch, and the MCP write tool are denied. Reviewer definition

The project config allows reads, asks for edits by default, and denies Bash outside its allowlist. It also retains the local graduate-triage MCP from the course history. Fifth Pick’s TypeScript review adapter correlates the named command and Reviewer task through an invocation marker and task call ID. A fixed-argument Python bridge verifies the exact review material digest and replays prior receipt state under a lock. The adapter transports the response and leaves permissions to the host and dispatch to the Controller. OpenCode config · Review adapter · Python bridge

PASS must match the exact proposal version. Malformed input stops. A first FAIL can authorize one Builder dispatch only when the current confirmation newly persists REVISION_ATTEMPT. Replay and uncertainty stop. A correction can remove selections only, and the revised proposal requires a matching PASS. CONCERNS and a second FAIL stop automated correction and surface findings to Joseph. The approved amendment permits an explicit, reasoned Joseph acknowledgment of CONCERNS for an uncorrected exact proposal. Harness lifecycle · Decision rules
